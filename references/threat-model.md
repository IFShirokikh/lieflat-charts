# Модель угроз

## Защищаем

- пользовательские значения, переданные в JSON;
- готовый HTML при локальном открытии через `file://`;
- процесс сборки от случайного вывода данных в лог;
- целостность зафиксированных библиотек, шрифтов и карт.

## Считаем недоверенным

Все поля JSON, включая подготовленные агентом. Возможные атаки: HTML/SVG-XSS, закрытие тега `script`, URL и `javascript:`-навигация, обработчики событий, прототипное загрязнение, чрезмерно большие данные и специальные числовые значения.

## Защиты

- строгий allowlist полей и контрактов по профилю;
- запрет HTML, URL и кода во входных строках;
- Base64 в неисполняемом блоке вместо интерполяции данных в HTML/JS;
- создание текста только через `textContent`, графиков — через фиксированные опции ECharts с `tooltip.renderMode = "richText"`;
- CSP с `default-src 'none'` и `connect-src 'none'`;
- отсутствие внешних ресурсов, форм, iframe, worker и навигации;
- проверка хешей исполняемых скриптов и вендорных файлов;
- атомарная запись результата.

## Не защищаем

Компрометацию самого агента, браузера, расширений, ОС, подмену репозитория до проверки хешей и ручную пересылку исходных данных. Для особо чувствительных данных агент и рабочее окружение должны иметь отдельную организационную политику доступа; этот репозиторий её не заменяет.
