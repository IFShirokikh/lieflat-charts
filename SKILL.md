# Lieflat Charts

Создавай графики только через локальный компилятор. Не пиши итоговый HTML вручную: разделение недоверенных данных и доверенного рендерера является основной защитой от XSS и утечек.

## Рабочий процесс

1. Определи, нужен отдельный график или полный отчёт. Отчёт выбирай только при явном запросе на отчёт, обзор, white paper, dashboard или подобную цель.
2. Прочитай `catalog.md`; для отчёта дополнительно прочитай `report-catalog.md`. Зафиксируй технический ID шаблона.
3. Подготовь JSON версии 1 по `references/spec-v1.md`. Используй только `locale: "ru"`; пользовательские данные сохраняй дословно, не переводи имена и значения.
4. Собери файл:

   ```bash
   node scripts/build-offline.mjs --spec input.json --out result.html
   ```

5. Компилятор сам проверяет результат побайтовым сравнением с канонической сборкой. Для повторной проверки запусти:

   ```bash
   node scripts/validate-output.mjs result.html
   ```

6. Перед передачей открой файл через `file://` и проверь читаемость длинных русских подписей.

## Ограничения безопасности

- Считай все входные строки недоверенными, даже если их подготовил агент.
- Не добавляй в спецификацию HTML, URL, JavaScript, обработчики событий или произвольные опции ECharts.
- Не изменяй `scripts/runtime.js` ради одного набора данных. Новое поведение добавляй как проверяемый тип шаблона.
- Не подключай CDN, Google Fonts, внешние изображения, аналитику, телеметрию и локальный веб-сервер.
- Не отключай CSP и не обходи валидатор результата.
- Значения данных не должны попадать в логи или сообщения об ошибках.

Подробная модель угроз находится в `references/threat-model.md`. При обновлении ECharts, шрифтов или GeoJSON следуй `references/vendor-update.md` и обновляй контрольные суммы.

## Цвет и язык

Используй одну палитру на результат: `mono`, `palm`, `porcelain`, `wire` или проверенную custom-палитру из цветов `#RRGGBB`. Пользовательский интерфейс, подписи по умолчанию и сообщения должны быть русскими. Термины сверяй с `references/glossary.ru.md`.
